# SubQ Snap ranking evaluation — October 12, 2026

Keep the current Jev ranker active. SubQ Snap worked against real production data, but neither a ranking improvement nor a safe input reduction held consistently across both temporal cohorts. The experimental integration is isolated from active scoring. All changes remain uncommitted and unpushed.

The promising architecture for further evaluation is cached, profile-free article classifications plus a separate personalized relevance decision. The tested arbitrary quality/hype blend and batch scoring reduced discrimination; they should not become production defaults.

## Data and comparison

Read the live `srv-captain--feed` container on the SSH host supplied by the user. Took a consistent SQLite backup with SQLite's backup API; production tables were not changed. The snapshot at approximately `2026-10-13T03:05:00Z` (October 12 in Phoenix) contains 12,525 articles, 6,327 Jev scores, and 17,431 interactions.

Replayed preferences using only events before each training cutoff, including production feature normalization, feedback weights, decay, profile limits, and source history. Held-out articles were ingested after the cutoff. Candidate AI metadata was included only if processed by the first labeling event. Article age uses that event's time. Each label is an open without a downvote, or an explicit downvote; absent opens were not used as negatives. A stable SHA-256 article-ID sample spreads positives across the window.

- September 22 cutoff: 58 articles, 40 opens and all 18 eligible downvotes.
- September 1 cutoff: 80 articles, 40 opens and 40 sampled downvotes.
- The cohorts overlap by 34 articles: 104 distinct labeled articles, not two independent replications.
- Four currently visible, unlabeled articles supplied a separate present-profile API/input-cost smoke test.

The main comparison keeps the production `would_open` question unchanged and sends identical frozen states to Jev and SubQ. Requested Jev model `jev-latest` resolved to `jev-1.13.0`; SubQ used `subq-snap-preview`. Full input matches the production state shape. Compact shortens text and positive preferences, removes only exact repeated sentences, and retains all supplied dislikes/avoided sources. Minimal additionally drops the excerpt and reduces summary/positive preferences. Packed uses compact information with tuple-encoded profile rows and omits empty candidate fields.

## Ranking results

AUC measures whether an opened article ranks above a downvoted article in this selected sample; 0.5 is chance. Higher is better.

| Request                                               | September 22 cutoff, n=58 | September 1 cutoff, n=80 |
| ----------------------------------------------------- | ------------------------: | -----------------------: |
| Jev full, current question                            |                     0.835 |                    0.728 |
| Jev compact                                           |                     0.779 |                        — |
| Jev minimal                                           |                     0.806 |                    0.682 |
| SubQ full                                             |                     0.826 |                    0.743 |
| SubQ compact                                          |                     0.846 |                        — |
| SubQ minimal                                          |                     0.856 |                    0.659 |
| SubQ compact, three questions, relevance alone        |                     0.846 |                        — |
| SubQ three-question relevance/quality/anti-hype blend |                     0.711 |                        — |
| Jev compact packed                                    |                     0.753 |                        — |
| SubQ compact packed                                   |                     0.828 |                        — |
| Jev packed batch of 4 / 8                             |             0.746 / 0.770 |                        — |
| SubQ packed batch of 4 / 8                            |             0.790 / 0.715 |                        — |

The predeclared exploratory blend was `0.8*would_open + 0.1*evidence_quality + 0.1*(1-hype_speculation)`. Both its all-in-one-request version and the single relevance request plus classification version performed worse (0.711 and 0.714). This experiment provides no support for those weights.

Paired day-cluster bootstrap intervals (3,000 samples, seed 20261012) all include zero for SubQ minus Jev full:

| SubQ arm | September 22 AUC difference, 95% interval | September 1 AUC difference, 95% interval |
| -------- | ----------------------------------------- | ---------------------------------------- |
| Full     | -0.009 [-0.125, +0.095]                   | +0.015 [-0.067, +0.101]                  |
| Minimal  | +0.020 [-0.101, +0.129]                   | -0.069 [-0.148, +0.026]                  |

On the earlier-cutoff sample, SubQ full's top 10 contained 10 opens versus Jev full's 7. This is encouraging observational evidence, but the sample and intervals do not establish a production uplift.

Important limits: opens are weak, exposure-biased positives; there are no impression/rank logs or randomized treatment. Most labels came from NYT, with smaller Verge and Greater Greater Washington groups. Current article text and a single current metadata row cannot recover every historical version. Stored heuristic scores already include feedback (their apparent AUC was 1.0), and stored Jev scores can include future profiles or stale results, so stored baselines are excluded from conclusions. Early raw summaries also treated unavailable AI composites as zero; the exporter now emits null, and none of those baseline metrics is used here. Precision and Brier are conditional on the sampled class mix, not production calibration. Evidence/hype outputs have no human truth labels in this dataset.

## Input cost and latency

Actual API-reported input tokens for the same 58 articles:

| Input             | Jev tokens | Reduction from Jev full | SubQ tokens | Reduction from SubQ full |
| ----------------- | ---------: | ----------------------: | ----------: | -----------------------: |
| Full              |    112,150 |                       — |      82,819 |                        — |
| Compact           |    104,771 |                    6.6% |      76,036 |                     8.2% |
| Minimal           |     87,284 |                   22.2% |      61,443 |                    25.8% |
| Compact packed    |     76,583 |                   31.7% |      55,324 |                    33.2% |
| Packed batch of 4 |     39,148 |                   65.1% |      31,587 |                    61.9% |
| Packed batch of 8 |     32,799 |                   70.8% |      27,534 |                    66.8% |

Batching shares the reader profile once across articles, while each candidate still has its own Noul question. The savings are real, but the larger batches changed scores and reduced AUC. Tuple packing also changed model behavior despite preserving the compact information. Retaining full Jev inputs is the evidence-supported default for now.

Full single-article requests averaged 145 ms for Jev and 205 ms for SubQ in the main run. A three-question SubQ request averaged 285 ms. These are sequential-client round-trip observations, not service latency guarantees.

The profile-free cached-classification experiment asked only evidence quality and hype/speculation on all 58 compact candidates: 29,926 input tokens, about 516 per article. The combined personalized three-question request used 87,868 tokens. This is a 66% reduction for a different, narrower task; both the reader profile and relevance question were removed. Evidence scores differed by a mean absolute 0.072, so profile/question context should not be treated as neutral. Classifications should be cached per article content/model/question version rather than repeated per reader or ranking refresh. They cannot replace the LLM's generated summaries/topics.

Twelve real article-image pairs successfully exercised the multimodal API. Images added 3,030 total input tokens (~253 each), increased mean round trip from 462 ms to 1,315 ms, and increased `would_open` by 0.029 on average. The image subset has 11 opens and one downvote, and no quality annotations: there is no validated image-ranking benefit. Do not attach every article image by default.

Across all logged experiments and the sampling pilot, 1,288 recorded requests returned usable responses with zero recorded API failures. Estimated input list-price cost is $0.0855, excluding access probes and any unlogged in-flight pilot request. [SubQ publishes $0.05/M input with free outputs](https://subq.ai/introducing-subq-snap); [Jev publishes $0.042/M input with free outputs](https://typesafe.ai/blog/introducing-system-one-models-and-jev). Prices and tokenizer overhead differ; byte counts are not billed token counts.

## Review and reproduce

Aggregated results without reader-profile payloads are in `subq-snap-2026-10-12.json` beside this report. Frozen cohorts, raw response records, run logs, and masked key-creation proof are kept privately at:

`/home/steven/.local/share/feed-me-maybe/evaluations/2026-10-12-subq-snap/`

The approved dashboard key is named `feed-me-maybe-ranking-eval` and stored at `/home/steven/.config/feed-me-maybe/subq-ranking-eval.key` with mode 0600. No key is in the repository or report. Jev's production credential continues to use its existing Swarm secret.

```sh
# Export from a consistent read-only SQLite snapshot.
python3 scripts/export-decision-cohort.py SNAPSHOT.db cohort.json \
  --profile temporal --cutoff 2026-09-22T00:00:00Z \
  --as-of 2026-10-13T03:05:00Z

# Each replay makes paid provider calls. Existing successful calls resume.
JEV_API_KEY_FILE=/secure/jev.key \
SUBQ_API_KEY_FILE=/home/steven/.config/feed-me-maybe/subq-ranking-eval.key \
node scripts/evaluate-decisions.ts cohort.json results.jsonl

# Summarizing makes no API calls and requires no credentials.
node scripts/evaluate-decisions.ts --summarize results.jsonl

# For packed single requests, transform states using buildPackedDecisionInput
# and select --variants full. Batch that same transformed cohort with:
node scripts/evaluate-decision-batches.ts packed-cohort.json batches.jsonl --batch-size 4

# Export JEV_DECISION_QUESTIONS as JSON and compact states for image tests.
python3 scripts/evaluate-decision-images.py compact-cohort.json images.jsonl \
  --questions questions.json --limit 12

# Candidate-only states and two classification questions use the same runner.
python3 scripts/evaluate-decision-images.py static-cohort.json static.jsonl \
  --questions static-questions.json --text-only --limit 58

npx vitest run src/lib/server/ai/decision-input.test.ts
python3 -m unittest scripts.test_export_decision_cohort -v
npm run check
```
